# research (bandori-playlist-maker)

> **브랜치 범위**: 이 브랜치는 새 알고리즘·모델·분석 방법을 검증하는 연구 전용 **단일 상시
> 재사용 브랜치**다(`data`·`tools`·`document-archive`와 동일한 패턴). 연구 주제 하나당 새
> git 브랜치를 파지 않고, 이 브랜치의 `topic/` 아래에 **주제별 폴더**를 하나씩 추가한다.
> `main`(배포 앱 소스)에는 **머지하지 않는다** — 앱 소스·문서 등 연구에 불필요한 파일은 이
> 브랜치에 두지 않는다. 상세 정책은 `main`의 `git-rules.md` "research" 절 참조.

## 주제 폴더 표준 구조

연구 주제 하나당 `topic/<주제>/`를 만든다. 모든 주제 폴더는 아래 구조를 따른다:

```
topic/<주제>/
├── src/
│   └── <method-N>/    # N번 방법론의 소스코드 전부 + 그 방법이 무엇인지·어떻게
│                       # 실행했는지 간략한 README.md
├── fig/                # 플롯 산출물
├── report/             # 이 주제 안에서 진행한 소규모 방법론·아이디어의 실행·검증 결과 보고서
├── ref/                # 사용자가 넣어두는 레퍼런스 자료
└── paper.md            # 연구 종결 시 report/ 를 취합해 초록논문 형식으로 작성
```

- `src/<method-N>/`: 방법론(접근법)이 여러 개면 `method-1`, `method-2`처럼 번호를 매겨 나눈다. 각
  폴더 안의 `README.md`에는 **① 이 방법이 무엇인지(간단한 소개)**와 **② 어떻게 실행했는지**를
  둘 다 간략히 적는다 — 코드만 보고는 방법론의 의도를 알기 어려우므로 소개 없이 실행법만
  적지 않는다.
- `fig/`: 정성 스캔용 플롯·그래프 등 시각 산출물.
- `report/`: 방법론 하나 또는 아이디어 하나를 실행·검증한 결과를 기록하는 소규모 보고서. 여러 개
  쌓일 수 있다(방법론별로 하나씩 등). **아래 "보고서·논문 공통 작성 구조"를 그대로 따른다.**
- `ref/`: 이 주제에 필요한 참고자료(논문·문서 등)를 사용자가 직접 넣어두는 곳.
- `paper.md`: 연구가 종결되면 `report/`의 내용을 취합해 초록논문 형식으로 작성한다. **아래
  "보고서·논문 공통 작성 구조"를 그대로 따른다.**

## 보고서·논문 공통 작성 구조

`report/*.md`·`paper.md` 등 이 브랜치에서 작성하는 **모든 보고서·논문**은 아래 5개 절을 이
순서로 따른다(섹션 번호·소제목 문구는 자유, 순서와 하위 구조는 고정):

1. **배경**: 왜 이 실험을 시작하게 됐는지 작성한다. 이는 보통 연구제안자(사용자)가 작성한다 —
   작성자가 임의로 동기를 지어내지 않는다.
2. **방법**: 실험 항목(조건·방법론)이 여러 개면 항목 하나당 방법 절 하나를 별개로 작성한다 —
   여러 항목을 한 절에 뭉뚱그리지 않는다. 각 방법 절은 아래 세 하위 항목을 이 순서로 포함한다.
   1. **용어 정리**: 이번 연구에 쓰이는 키워드·변수·실험조건 등의 정의. 최대한 간결하게, 필요한
      말만 적는다. 정의가 길어지면(예: 변수가 많거나 조건이 복잡한 경우) 본문에 다 적지 말고
      별도 레퍼런스 파일을 만들어 그 파일 위치를 안내한다. 가능한 한 불렛 형식으로 작성한다.
   2. **실험 방법**: 이번 실험의 구현 방법을 순서대로 기술한다. 넘버링 불렛(`1.` `2.` `3.` …)으로
      작성한다.
   3. **평가 방법**: 실험 구현 결과값에 대한 해석 방법과 해석 기준을 기술한다. 특히 "score"(또는
      그에 준하는 판정 지표)를 무엇으로 정의하는지, 어떤 입력에서 어떤 계산/규칙으로 산출하는지를
      반드시 명시한다 — 사람이 매긴 값이면 척도와 채점 기준을, 규칙기반 자동 계산이면 계산식·
      조건문·임계값을, 통계 검정을 쓰면 어떤 검정을 왜 썼는지를 적는다.
3. **결과**: 실험 항목에 대한 결과값을 표나 플롯으로 표시하고, 그에 대한 해석을 작성한다.
4. **결론**: 결과를 모두 종합해 최종적인 결론을 기술한다.
5. **레퍼런스**: 앞서 언급한 내용 중 자세한 설명이 필요하지만 너무 길어서 이 보고서 본문에 못
   담은 경우, 그 내용이 있는 파일의 출처(경로)를 적는다. 해당하는 내용이 없으면 이 절 자체를
   생략한다.

## data/

연구 스크립트가 참조하는 데이터셋 스냅샷 — `data` 브랜치의 `data/`를 그대로 가져온 것이다(9개
CSV/JSON + `legacy/`). `data` 브랜치가 갱신된 뒤에도 이 스냅샷은 자동으로 따라가지 않으므로,
최신 데이터가 필요한 연구를 새로 시작할 때 `git checkout data -- data`로 다시 가져온다.

## 산출물 3종의 목적지

- **분석용 스크래치 데이터**(중간 계산·샘플 서브셋 등): 각 주제 폴더 안에 자유롭게 둔다 —
  이 브랜치는 `main`에 머지되지 않으므로 여기 쌓인 내용이 `main`을 오염시키지 않는다. 대용량
  바이너리는 각 폴더의 `.gitignore`가 걸러낸다.
- **검증돼서 정식 채택할 데이터**(예: `data/songs_master.csv`에 새 컬럼 추가): 이 브랜치가
  직접 `data/`를 고쳐 `main`으로 보내지 않는다. 채택된 데이터 변경은 새 `feature/*` 브랜치
  (또는 자동화라면 `data`/`tools` 브랜치)에서 다시 정식으로 반영한다. 이 브랜치는 "이 데이터가
  이렇게 바뀌어야 한다"는 근거만 만드는 역할이다.
- **연구 보고서(`report/*.md`, `paper.md`)**: 진행 중에는 주제 폴더 안(`report/`)에 자유롭게
  쌓아두되, 연구가 종결돼 `paper.md`(초록논문 형식)까지 작성되면 그 `paper.md`만
  `document-archive` 브랜치의 `archive/last-papers/research/`로 별도 커밋한다. 중간 `report/*.md`는 이
  브랜치에 그대로 둔다(최종 종합만 반영).

## 새 연구 주제를 시작할 때

새 git 브랜치를 만들지 않는다 — `topic/` 아래에 새 폴더(예: `topic/lyrics_embedding/`)를
추가하는 것으로 시작한다. 연구 결과가 유의미하지 않으면 저장소 소유자와 확인 후 해당 폴더를
정리한다.
결과가 채택되면 새 `feature/*` 브랜치를 생성해 정식 기능(`src/`)으로 구현한다 — 이 브랜치를
그대로 `main` 대상 PR로 열지 않는다.
